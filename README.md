# 空岛生存（SkyIsland）

第一人称体素空岛生存 + 枪械战斗游戏。**纯 Java + LWJGL 从零手写体素引擎**，不使用任何现成游戏引擎。

- 项目目录：`F:\minecraftspace`
- 当前阶段：**M2.1 Combat Feel & Readability —— 脚本侧全 PASS**（三门禁 27/0、60/0、121/0；815 单测 0 失败）｜**待一次 ≥ 10 分钟人工试玩**（清单 `docs/testing/M2_1_PLAYTEST_CHECKLIST.md`）｜产品版本 **0.3.1-M2_1-COMBAT-FEEL**｜文档版本 **v0.3**
- 上一里程碑：M1.5 Front-End & Settings **PASS**（`0.2.5-M1.5-FRONTEND`）
- 日期：2026-09-21
- 产出方式：游戏开发工作室编排（策划 `design-strategist` 出 PRD，工程 `engineering-lead` 出技术约束，主理人汇编与一致性核查）

## 三、跨文档一致性核查（主理人执行）

核查了 PRD 与技术附录逐条对齐情况，发现并修复 3 处冲突：

| 冲突点 | 冲突内容 | 处理结果 |
|--------|----------|----------|
| 构建链 | PRD 原写「Maven 3.6.1 为唯一构建链」，但 `maven-shade-plugin` 系统要求为 Maven ≥ 3.6.3，3.6.1 无法驱动，M0 打不出包 | 用户裁决升级本机 Maven 至 **3.9.9**，两份文档已同步 |
| 渲染后端抽象 | PRD 原表述偏向「可出 Web 版」 | 已统一为「存在可插拔接口 + 空实现后端可编译」，**不承诺 Web 运行能力**（LWJGL 为 JNI 原生绑定，浏览器不可用） |
| 最小架构预留成本 | PRD 10.3 原标注「待与程基岩确认」，三项成本预估偏高 | 已依工程结论回写：逻辑与渲染 / 输入解耦、世界状态可序列化、时间步进与帧率解耦均为**零成本**；「世界改动单一入口与状态快照接缝」为低成本（各约 0.5%–1%）。整体 ≤2% |

### M1.5 交付了什么（可进出的完整外壳）

主菜单 + 暂停菜单 + 设置界面（灵敏度 / FOV / VSync / 反转 Y / 显示 FPS）+ **键位重绑（冲突检测与确认）**
+ 设置独立持久化（损坏自恢复）+ 界面状态机与光标模式联动 + 暂停时物理完全冻结
+ **破坏反馈：方块面 10 段裂纹** + 退出走完整收尾（保存 → GL 释放 → GLFW 终止）。

同时修复了两个人工试玩暴露的真实缺陷：**帧级输入量错配**（零逻辑步丢输入 / 多逻辑步重复施加）
与**松键后玩家永久平移**（速度不衰减 + 失焦不释放按键）。

**M1.5 明确不含**：枪械、弹药、换弹、怪物与 AI、生命值、饥饿、昼夜循环、掉落物实体、
合成服务、背包与合成界面、**音频后端（含 PRD 要求的挖掘/破坏音效）**、粒子系统、
`TextureArray`、正式岛屿生成器与动态区块加载。详见 M1.5 报告 §6.3/§6.4 与 §6.1 的 **T-8.9**。

### M2 交付了什么（可以开枪的完整闭环）

手枪开局装备 + 左键开火（4 发/秒节流）+ R 换弹（1.2 秒）+ 右键瞄准（FOV 70→45°、移速 ×0.60）
+ Hitscan 最近命中（隔实体方块不能命中怪物）+ 距离衰减（超出有效射程每格 ×0.9，下限 20%）
+ 近战怪追逐与攻击 + 生命 / 死亡 / 3 秒重生 + 命中与破坏粒子 + 曳光
+ 准星两形态与目标高亮 + 10 颗心生命条与「12 / 36」弹药计数
+ **简体中文界面（自研 CJK 点阵字库，1352 字形，离线烘焙）**。

过程中修掉四个真实缺陷，最严重的一个是**玩家的枪在存档里静默消失**：
存档按「方块」表序列化快捷栏，而手枪的 `blockRuntimeId()` 是 −1，读档后变回空气。
当时 M1 自测 **27 项断言全绿**，唯一的迹象是日志里两条**无人断言**的告警 ——
"断言全绿"不等于"没有缺陷"。

> **M2.2 修订：换弹不再被移动打断。** M2 交付时 R 换弹的口径是「移动即取消换弹」，该规则
> 已在 M2.2 收尾时**废止**（PRD 5.4.3 → v0.3.2-r1）：现在按 R 之后可以边走边换，
> 1.2 秒走满即完成上膛；弹药仍只在完成这一刻转移，换弹期间仍不得开枪。
> 相关的 `cancelReload()` / `reloadsCancelled` / `onReloadCancelled` / `MSG_RELOAD_INTERRUPTED`
> 已整体删除（不留死代码），自测阶段同步由 `RELOAD_INTERRUPTED` 改写为 `RELOAD_WHILE_WALKING`。
> 上述第三行因此不再写"移动打断"。

**M2 当时明确不含**：音频后端、昼夜循环与时间 HUD、饥饿、合成、其余 3 把枪与 3 种怪、
蹲下、完整背包界面。逐项登记见 M2 报告 §7 的 G1–G9。
（其中**音频后端已由 M2.1 交付** —— 见下一节。原句把"当时的实现缺口"写成了产品口径，
留在这里会主动误导下一位读者。）

**M2 新增了"能证明自己在真实窗口里跑完一场枪战"的手段**：`M2CombatSelfTest`（进程内 `PlayerIntent`
注入，15 阶段 / 105 断言），断言全部带实测值 —— 例如换弹完成实测 1.2000 s（第 72 步）、
瞄准移速比实测 0.600000、三发伤害序列 [8, 8, 8]、45 格外伤害实测 2、破坏粒子实测 9 个（PRD 区间 8–12）、
死亡到重生实测 3.0000 s、读档后手枪 ×2 与手枪弹 ×24 仍在且 `warnings = []`。

**收口轮还查出一个更深的问题，值得单独记**：M1.5 的界面自测门禁被 M2 打红了，而它**此前一直是一盏假绿灯**——
那个"按住左键挖掘"的阶段之所以绿，是**外部真实鼠标滚轮**偶然把手枪切走了才成立的。
根因是 M2 让"手持枪械时左键是开火不是挖掘"，而 `M1_5UiSelfTest` 没有像 `M1ScriptedSelfTest` 那样
先切到方块物品。修完之后它的容差是**收紧**的（±1.0° → ±0.05°），并且**污染窗口作废重测**而非放水。
**教训："绿灯"必须能解释自己为什么是绿的。**

### M2.1 交付了什么（Combat Feel & Readability）

弹药口径改为**后备无限**（弹匣仍 12、仍需按 R、HUD 显示 `12 / ∞`；M3 再恢复有限后备）
＋ **枪口火光 / 更亮更粗的曳光 / 撞击粒子 / 命中标记 / 轻微后坐**
＋ 怪物由"单盒体"改为 **8 部件体素人形**（头 / 躯干 / 双腿 / 双臂 / 双眼，含行走起伏、受击闪白、攻击前冲）
＋ **第一人称手持物**（枪 / 方块 / 空手三种形态，含 idle bob / 开火后坐 / 换弹下压 / ADS 收拢）
＋ **最小音频链**（`lwjgl-openal`，5 个程序合成占位音，接设置里的音效滑杆）。

**这一轮最值钱的产出不是"把功能做完"，而是抓出 8 处"已定义、从未被调用"的死代码。**
枪口火光、命中标记、开火后坐力**全部写在代码里、却从来没有被调用过**：编译通过、
815 条单测全绿、M1 与 UI 门禁全绿，而屏幕上一样都看不到。
更狠的一处是 `CombatFxRenderer.init()` 在加"枪口闪光"时把**曳光的缓冲分配整段顶掉**了
（指纹：`dispose()` 释放三组、`init()` 只分配两组），门禁 m2 因此**崩在 5.6 秒、只跑到第 31 条断言**，
而 NPE 堆栈指向渲染循环、离真因隔了三层。

因此 `M2CombatSelfTest` 的表现层断言从 107 条增到 **121** 条，且**只有接线真的存在才会变绿**；
同时新增 `CombatFxRendererLifecycleTest`，用三条**与特效组数无关**的结构断言
（VAO 组数 == 缓冲组数 / 分配后无 null / 容量来自同名常量）把这一类编辑事故挡在门禁之前。

**第 4 次撞上同一条判据：`断言全绿 ≠ 无缺陷`。** 这一次的形态最隐蔽 —— 不是断言判错了，
而是**那几条行为根本没有对应的断言**（`totalSpawnCalls > 0`、`totalBreakParticles > 0`
之类的邻近读数照样成立）。详见 `docs/testing/M2_1_COMBAT_FEEL_REPORT.md`。

### 创造模式：怎么开、怎么选方块

**在游戏里连按两下空格。** 直接进创造**并且立刻起飞**。

同一个键走完三态：

| 现在 | 双击空格后 |
|---|---|
| 生存，没开创造 | **进创造 + 直接起飞** |
| 创造中 | **只**切换飞行（开/关），**永不**退出创造 |

**双击空格自始至终只是「飞行开关」**（2026-10-09 改）。
退出创造会话走 **ESC → 暂停菜单 → 「结束创造模式」**。

> ★ **为什么不再用"第三次双击退出创造"**（这是主理人实测后改的）：
> 站着不动时 `flying` 仍可能是 true（悬停在地面上方），
> 而它与"没在飞"**看起来一模一样**。于是同一个键在**看起来一样的两种状态下**
> 做完全不同的事，且玩家无从预判。
> 实测那个版本的结果是：按 Ctrl 降到地面 → 第 1 次双击停飞 →
> **第 2 次退出创造、能力全没** → 第 3 次才重新起飞。
> 一个手感键静默拿走你的全部能力，比它什么都不做更糟。

**HUD 会常驻显示「飞行中 · 空格上升 / Ctrl 下降 · 双击空格关闭」**
或「创造会话中 · E 取方块 · ESC 结束创造模式」——
状态看得见，操作才可预测。

> **唯一的残留代价**：用无限方块盖的建筑**仍然留在世界里**，退出后也在。
> 这在不改存档格式的前提下无法消除（要给每个方块位加"创造来源"标记 = 存档格式破坏性变更）。
> 你已经知情接受，所以游戏会在进/出创造时各弹一条提示写明这件事。

选方块：按 `E` → 点「创造」标签 → **左键**点方块（64 个到**鼠标光标**上）
→ ★ **切回「背包」标签，左键点底部 9 个快捷栏格之一**
→ `E` 关闭 → 按数字键 → **右键**放置。
在「创造」页上快捷栏**点不动**（那一页处理完面板点击就返回）——
停在第 3 步的症状是"方块跟着鼠标，但按右键放不出来"。

**怎么选方块**（这段不显然，是最常被当成 bug 的地方）：

1. 按 `E` —— 创造模式下背包有**两个标签**：`背包` / `创造`；
2. 点「创造」标签 —— 出现全部可放置方块的网格；
3. **左键**点一个方块 —— 64 个出现在**鼠标光标**上（规格要求不占背包格）；
4. ★ **切回「背包」标签，左键点底部 9 个快捷栏格之一** —— 这一步不能省：
   在「创造」页上快捷栏**点不动**（那一页会先处理面板点击就返回）。
   若你停在这一步还没进背包，会看到"64 个方块跟着鼠标，但按右键放不出来"；
5. 按 `E` 关闭，按那个槽位的数字键（1–9）；
6. 在世界里**右键**放置 —— **不消耗**，可以一直放。

好处是一次备好 9 种方块：滚轮在空手时循环切换快捷栏。

**创造模式给了什么**（PRD §5）：全部可放置方块、无需合成、瞬时破坏（按住左键连续破坏）、
放置不消耗、**免疫伤害**、掉进虚空停在底部不死、飞行。

**开会话不会没收你手上的枪**（M2 铁律：物品不得凭空消失）。
退出创造后枪还在 —— 因为这本来是同一个世界。

### ⚠ 关于 Shift 键与中文输入法

**游戏本身没有"中英文切换"功能**（`Action` 枚举里没有这个动作，
UI 只有 zh-CN 一种语言）。切换来自 **Windows 输入法**。

### 已测量：这个问题在窗口这一层拦不住

项目为此写了一个 JNI 桥去摘输入法上下文，并在启动日志里打出机器读数：

```
[窗口] IME（窗口创建后）：子类已装=true，IMM前=有，IMM后=无
ime = 子类调用=1066  WM_IME_SETCONTEXT=0  WM_INPUTLANG=0  本进程收到的SHIFT键事件=0
```

逐条读：**输入法的 IMM 上下文确实被摘掉了**（有 → 无）；
**窗口子类确实在工作**（收到 1066 条消息）；
但 `WM_IME_SETCONTEXT` 与 `WM_INPUTLANGCHANGEREQUEST` **一条都没来过**。

⇒ 结论：**输入法根本不与本游戏窗口交互**，它在窗口消息派发**之上**吞键。
任何窗口级 API（IMM32 或窗口过程子类）都拦不住它。
那层只能用 TSF 的按键管理器（`ITfKeystrokeManager`）处理，
属于输入法版本相关的 COM 路径，脆弱且无把握 —— 所以**不做**，
而是把它如实记在这份文档里。

### 所以：飞行下降默认键改成了 **左 Ctrl**

```
KeyBindings.java : Action.CROUCH → GLFW_KEY_LEFT_CONTROL
```

左 Ctrl 是中文输入法基本不碰的键（Minecraft 等游戏的中文用户也普遍这么改）。
这一条是**唯一可靠的修法**：不把关键操作绑在会被吞的那个键上。

**想要 Shift 的话，两条路**：

1. **关掉输入法的「用 Shift 键切换中/英文」**（推荐，一劳永逸）
   `设置 → 时间和语言 → 输入 → 高级键盘设置`；
   然后在游戏设置里把 `Fly Descend` 改回左 Shift。
2. 只在设置里把 `Fly Descend` 改成别的键（它本来就是可重绑的）。

> 背包里的 `Shift + 左键` 快速搬运**仍然直读 Shift**，刻意没进键位表：
> 那是鼠标操作的修饰键不是游戏动作，放进键位表会让"改 Fly Descend"顺手把它也改了。
> 如果这一步也失灵，请走上面第 1 条。

|---|---|---|

四步就能确认这确实是两把枪（不是"同一把枪换了名字"）：

1. 按 `3` —— 手上的模型与背包图标都与手枪不同（`GUN_PARTS` vs `SMG_PARTS`，枪口位置也不同）；
2. **单击**左键 vs **按住**左键 —— 手枪单击恰好一发，冲锋枪按住一梭子；
3. 打空按 `R` —— 手枪约 1.2 s、冲锋枪约 1.5 s；换弹过程中按住 `W` 走动，换弹**不会**被打断；
4. 按 `F4` 刷怪 —— 手枪更重更慢，冲锋枪更快更轻（射程 32 vs 24）。

**不要用旧存档判断当前版本。** 开局装备只在**新世界**发放，读旧档不会补发 ——
你会看到一套与当前版本不符的背包，并很容易因此得出"XX 没做出来"的错误结论。
`play.bat` 检测到已存在的存档时会**显式警告**，不会假装正常。

**后备弹药口径（可切换）**：两个入口都**默认无限后备**（Debug / Prototype 口径，v2 §19-7）——
换弹补满弹匣而不动背包，方便连着试射速与换弹时间。产品默认仍是**有限**的 Survival 口径
（v2 §19-6：换弹真实从背包里扣，开局 24 发）；把启动器 `java` 行里的
`-Dskyisland.infiniteReserve=true` 删掉（或改成 `false`）就是正式口径。
开关解析很严：**只有显式 `true`** 才算数，`=1` / `=yes` / 拼错一律留在有限的**安全侧**（错字不该改变玩法口径）。
启动时会打印本局生效的口径（`后备弹药口径 : 无限（PROTOTYPE …）` / `有限（SURVIVAL …）`），
所以"为什么弹药不扣"永远不需要靠猜。
