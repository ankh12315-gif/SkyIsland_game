## 2. 产品概述

### 2.1 一句话定位

用**纯 Java 从零手写体素引擎**实现的《我的世界》式第一人称空岛生存游戏，核心差异化是**空岛 + 枪械战斗**。

本作为**单机生存**，联机为后续迭代规划（原决策 12 的 2–4 人合作已推迟，详见第 7 章），首版不实现任何联机功能。

### 2.2 设计支柱

设计支柱是判断一切设计取舍的最高依据。当两条需求冲突时，按支柱排序裁决。

| 编号 | 支柱 | 释义 | 对应决策 |
|------|------|------|----------|
| P1 | **虚空之上的生存张力** | 可活动空间有限、资源空间分离、坠落即死。所有系统须强化「脚下无地」的持续压迫感，禁止设计让玩家高枕无忧的无风险区域 | 决策 3、5、10、15、16 |
| P2 | **自造枪械的战斗节奏** | 枪与弹药全部靠合成，枪械本身是长期进度目标而非开局装备。战斗节奏围绕「造枪—消耗弹药—再采集」形成闭环 | 决策 6、7、8 |
| P3 | **昼夜驱动的推进节奏** | 白天外出采集与建造，夜晚防守与战斗。昼夜是主循环的节拍器，而非纯视觉表现 | 决策 8、14 |
| P4 | **可扩展的体素基座** | 架构与内容分离，方块、枪械、怪物、配方均以数据驱动方式扩展，支撑长期迭代成正式作品 | 决策 1、4、17、20 |

### 2.3 目标玩家画像

| 维度 | 描述 |
|------|------|
| 核心画像 | 喜爱《我的世界》空岛玩法、对体素沙盒有耐心、期待「从零建造」成就感的玩家 |
| 次要画像 | 喜爱轻量射击对抗、希望在沙盒里获得战斗压力的玩家 |
| 游玩时长 | 单次会话 30–90 分钟；单人长线存档 10 小时以上 |
| 平台 | Windows PC（键盘 + 鼠标） |
| 前置经验 | 熟悉第一人称操作与 WASD 键位；无需阅读教程即可上手（依赖通用键位习惯与即时提示） |
| 不覆盖人群 | 追求剧情与结局的玩家（本作无结局）；追求高拟真硬核射击的玩家（首版无后坐力/散布） |

### 2.4 与《我的世界》空岛玩法的差异化

| 维度 | 《我的世界》经典空岛 | 本作 | 差异价值 |
|------|----------------------|------|----------|
| 空间结构 | 单一小岛，靠刷怪掉资源 | 主岛 + 4 座资源小岛，资源空间分离 | 强制玩家在岛屿间移动，放大坠落风险与探索动力 |
| 战斗 | 近战 + 弓，战斗为次要系统 | 枪械为主，昼夜刷怪 + 会还击的远程枪手 | 战斗成为独立支柱，夜晚形成明确的压力峰值 |
| 资源循环 | 依赖刷石机与刷怪塔 | 开局内置刷石机 + 小农田，矿物集中在资源小岛 | 前期无卡关风险，中后期靠远征资源岛获得枪械材料 |
| 成长曲线 | 无明确难度增长 | 威胁等级随天数递增，枪械进度与之对抗 | 提供「无结局」下的长期目标感 |
| 实现方式 | 官方/模组引擎 | 纯 Java + LWJGL 从零手写体素引擎 | 技术自主，架构专为长期迭代设计 |

## 3. 玩法主循环

### 3.1 三层循环拆解

| 层级 | 时长 | 循环内容 | 玩家动机 | 优先级 |
|------|------|----------|----------|--------|
| 分钟级 | 30 秒–3 分钟 | 采集（挖方块/打怪）→ 合成（背包内直接合成）→ 建造/射击 → 返回安全区 | 资源即时反馈；即时生存决策 | 【首版必须】 |
| 小时级 | 20–60 分钟 | 白天远征资源岛采集矿物 → 合成新枪械/弹药 → 夜晚防守增强的怪物 → 扩建主岛平台 | 枪械进度解锁；应对递增威胁 | 【首版必须】 |
| 长期级 | 数小时–数十小时 | 全岛屿探索完成 → 全枪械收集 → 建造大型工程 → 冲击挑战成就 | 建造成就；收集完整度；自我设定目标 | 【首版必须】 |

### 3.2 分钟级循环（微观）

1. 决定目标：采集材料 / 建造 / 防守 / 远征。
2. 执行动作：使用左键挖掘或开枪，右键放置或瞄准。
3. 结算产出：方块掉落物自动飞向玩家并拾取（拾取半径 2 格）；怪物掉落材料直接进背包。
4. 合成转化：按 E 打开背包，在背包内直接选择配方合成。
5. 消费/再投入：消耗弹药与饥饿值，决定回小屋休整或继续推进。

循环设计目的：保证任意 3 分钟内都有一次「决策—执行—获得」的完整反馈，维持短周期节奏。

### 3.3 小时级循环（中观）

1. 清晨（黎明）：结算新一天，威胁等级提升。
2. 白天（约 11 分钟）：主岛补给（刷石机产石、农田收麦），随后远征资源小岛采矿。
3. 黄昏（约 1 分钟）：返回主岛，布置防御（放置方块掩体、备弹）。
4. 夜晚（约 7 分钟）：应对刷怪与远程枪手，消耗弹药。
5. 深夜复盘：合成新弹药、修复防御工事、规划次日远征目标。

循环设计目的：以昼夜为节拍器，形成「扩张—收缩」的节奏张力。

### 3.4 长期级循环与内在目标设计（应对「无结局」）

由于本作无结局（决策 3），长期动力必须由内在目标补足。内在目标分三类：

#### 3.4.1 探索度

| 目标 | 衡量方式 | 奖励反馈 |
|------|----------|----------|
| 岛屿探索 | 5 座岛屿全部到达并在其上采集过矿物，记为探索度 100% | HUD 显示探索度进度；达 100% 解锁成就「群岛旅人」 |
| 资源采集完整 | 记录已采集的资源种类（共 8 类可采材料） | 背包界面显示收集图鉴，未采集项显示剪影 |

#### 3.4.2 建造里程碑

| 里程碑 | 达成条件 | 说明 |
|--------|----------|------|
| 扩岛工程 | 主岛平台面积扩展至 ≥ 48×48 | 玩家自主建造，系统仅记录并给成就 |
| 跨岛通路 | 建成至少 1 条连接主岛与资源岛的实体通道 | 用方块搭桥，允许悬空放置 |
| 防御工事 | 在主岛外围建成完整围墙（周长 ≥ 64 格的封闭结构） | 系统按方块连续性判定 |
| 扩建至 64×64 | 主岛平台扩展至 ≥ 64×64 | 长期建造目标 |

#### 3.4.3 成就系统（首版 12 项）

| 成就 | 达成条件 | 优先级 |
|------|----------|--------|
| 第一步 | 挖掘首个方块 | 【首版必须】 |
| 火力初现 | 合成首把手枪 | 【首版必须】 |
| 首杀 | 击杀首只怪物 | 【首版必须】 |
| 精准射手 | 单发命中距离 ≥ 40 格的怪物 | 【首版必须】 |
| 军械库 | 合成全部 4 种枪械 | 【首版必须】 |
| 弹药管够 | 累计合成 200 发任意弹药 | 【首版必须】 |
| 生存一周 | 存活至第 7 天 | 【首版必须】 |
| 生存两周 | 存活至第 14 天 | 【首版必须】 |
| 清道夫 | 累计击杀 100 只怪物 | 【首版必须】 |
| 群岛旅人 | 探索度达 100% | 【首版必须】 |
| 建筑家 | 达成「扩岛工程」 | 【首版必须】 |
| 虚空漫步者 | 在资源岛最远处建造并站立 30 秒 | 【后续迭代】 |

设计约束：成就仅做记录与展示，不提供数值增益，避免破坏生存平衡与 P1 张力。

### 3.5 循环断裂点自查

| 潜在断裂点 | 风险 | 首版缓解措施 |
|------------|------|--------------|
| 开局无枪、夜晚遭袭 | 首夜即死，负反馈过强 | 开局赠送手枪 + 24 发弹药；第 1 天威胁等级为基线 |
| 矿尽 | 主岛无矿，远征成本高 | 刷怪掉落矿石兜底；资源小岛矿物不耗尽 |
| 弹药枯竭 | 战斗中无弹 | 火药可稳定合成；怪物掉落火药 |
| 无结局导致中期迷失 | 玩家丧失目标 | 12 项成就 + 探索度 + 建造里程碑三重内在目标 |

## 4. 世界设计

### 4.1 世界总体参数

| 参数 | 数值 | 说明 | 优先级 |
|------|------|------|--------|
| 水平规模 | 主岛 32×32 | 玩家出生岛，边长以格计 | 【首版必须】 |
| 视距 | 6 区块（96 格半径） | 渲染加载范围 | 【首版必须】 |
| 世界高度 | y = 0 至 y = 127（128 层） | 可放置范围 y ∈ [1, 127] | 【首版必须】 |
| 主岛基准面 | y = 64（岛屿表面） | 玩家出生脚下方块顶部 | 【首版必须】 |
| 岛屿厚度 | 8–14 层（底部 y = 50–64） | 主岛从表面向下延伸的厚度 | 【首版必须】 |
| 目标帧率 | 稳定 60 FPS | Windows 优先 | 【首版必须】 |
| 岛屿总数 | 5 座（1 主岛 + 4 资源小岛） | 决策 5 | 【首版必须】 |

### 4.2 岛屿布局

坐标以主岛几何中心为原点 (0, 0)，水平面内计量。

| 岛屿 | 类型 | 中心坐标 (x, z) | 尺寸 | 距主岛边缘间隙 | 说明 |
|------|------|------------------|------|----------------|------|
| 主岛 | 出生岛 | (0, 0) | 32×32 | — | 含开局小屋、刷石机、小农田、少量树木 |
| 石矿岛 | 资源岛 | (48, 0) | 14×14 | 约 25 格 | 富集 石、煤、铁 |
| 森林岛 | 资源岛 | (-44, 12) | 14×14 | 约 21 格 | 富集 原木、泥土、小麦种 |
| 金属岛 | 资源岛 | (10, -48) | 12×12 | 约 26 格 | 富集 铁、铜、金 |
| 晶矿岛 | 资源岛 | (-6, 52) | 10×10 | 约 31 格 | 富集 晶体（稀有，高级枪械材料） |

布局设计意图：
- 4 座资源岛分列四个方向，避免单一路径疲劳；任意小岛均在 6 区块视距内可被看到远处轮廓，形成探索引导。
- 资源岛之间最近间距 ≥ 32 格，保证岛屿间跳跃/搭桥具备明确风险。
- 所有岛屿海拔基准一致（y = 64），降低远距离判读高度差的认知负担。

### 4.3 各岛资源分布表

| 资源类型 | 主岛 | 石矿岛 | 森林岛 | 金属岛 | 晶矿岛 |
|----------|------|--------|--------|--------|--------|
| 草/泥土 | 高 | 低 | 高 | 低 | 低 |
| 石 | 中 | 高 | 低 | 中 | 中 |
| 煤 | 低 | 高 | 无 | 中 | 低 |
| 铁矿石 | 无 | 高 | 无 | 高 | 中 |
| 铜矿石 | 无 | 低 | 无 | 高 | 中 |
| 金矿石 | 无 | 无 | 无 | 中 | 低 |
| 晶体矿 | 无 | 无 | 无 | 低 | 高 |
| 原木 | 低 | 无 | 高 | 无 | 无 |
| 小麦种 | 低 | 无 | 中 | 无 | 无 |
| 沙子 | 低 | 中 | 低 | 无 | 中 |

密度定义（每 100 格表面积的平均矿物格数）：高 = 8–12，中 = 3–6，低 = 1–2，无 = 0。

资源分布意图：
- 主岛不产铁、铜、晶体，强制远征（呼应 P1）。
- 火柴药（火药原料）所需煤与沙分布在石矿岛与森林岛，早期即可获得。
- 晶体集中在最远的晶矿岛（距主岛约 52 格），对应最高端枪械的稀有门槛。

### 4.4 昼夜循环

| 阶段 | 时长 | 环境表现 | 机制影响 | 优先级 |
|------|------|----------|----------|--------|
| 黎明 | 1 分钟 | 天空由暗转亮 | 停止刷怪；结算新一天，威胁等级提升 | 【首版必须】 |
| 白天 | 11 分钟 | 全亮 | 无刷怪；采集与建造主要时段 | 【首版必须】 |
| 黄昏 | 1 分钟 | 天空由亮转暗 | 开始刷怪 | 【首版必须】 |
| 夜晚 | 7 分钟 | 昏暗，火把成为主要照明 | 持续刷怪，压力峰值 | 【首版必须】 |
| 合计 | 20 分钟 | — | 一个完整昼夜 | 【首版必须】 |

补充规则：
- 一天 = 从黎明开始到下一次黎明前的完整周期；存活天数以黎明为结算点递增。
- 夜晚最低亮度为白天的 15%，火把照亮半径 6 格（首版无动态全局光照，采用固定衰减）。
- 【后续迭代】季节、天气（雨/雾）系统。

### 4.5 虚空规则

| 规则 | 定义 | 优先级 |
|------|------|--------|
| 虚空判定 | 未处于任何岛屿实体方块上方的空气区域即为虚空 | 【首版必须】 |
| 坠落致死线 | 玩家 y 坐标 < -8 判定虚空死亡（无视生命值，直接死亡） | 【首版必须】 |
| 虚空可见性 | 岛屿下方无任何地形，向下即见天空/雾；虚空底部渲染为深色 | 【首版必须】 |
| 放置限制 | 允许在虚空上方悬空放置方块（用于搭桥、扩建）；可放置区间 y ∈ [1, 127] | 【首版必须】 |
| 方块重力 | 沙子受重力：下方方块被挖空时沙子下落，但不造成伤害；首版除沙子外无重力方块 | 【首版必须】 |
| 坠落伤害 | 在虚空坠落过程中不结算普通坠落伤害，仅以触底判定致死 | 【首版必须】 |
| 【后续迭代】 | 虚空下方加入云层/深渊视觉；虚空边界软墙提示 | 【后续迭代】 |

## 5. 系统规格

### 5.1 方块与地形

挖掘耗时以空手（无工具）为基础，首版无工具系统。掉落物以默认（无附魔）计。

| 方块 | 硬度 | 挖掘耗时（秒） | 掉落物 | 可否堆叠 | 优先级 |
|------|------|----------------|--------|----------|--------|
| 草方块 | 0.6 | 0.6 | 泥土 ×1 | 是（64） | 【首版必须】 |
| 泥土 | 0.5 | 0.5 | 泥土 ×1 | 是（64） | 【首版必须】 |

#### 5.5.3 随时间增强的强度曲线

威胁等级以存活天数为输入。下表给出第 1 / 3 / 7 / 14 天的具体数值。

| 存活天数 | 生命倍率 | 伤害倍率 | 移动速度倍率 | 同时存活上限 | 远程枪手占比 | 大型怪占比 |
|----------|----------|----------|--------------|--------------|--------------|------------|
| 第 1 天 | ×1.0 | ×1.0 | ×1.0 | 8 | 10% | 0% |
| 第 3 天 | ×1.2 | ×1.15 | ×1.0 | 10 | 20% | 5% |
| 第 7 天 | ×1.5 | ×1.4 | ×1.05 | 12 | 35% | 12% |
| 第 14 天 | ×2.0 | ×1.8 | ×1.1 | 16 | 50% | 20% |

| 第 30 天【后续迭代】 | ×3.0 | ×2.5 | ×1.2 | 20 | 60% | 30% |

曲线公式（用于实现）：

- 生命倍率 = 1.0 + 0.075 × (天数 − 1)，上限 3.0
- 伤害倍率 = 1.0 + 0.06 × (天数 − 1)，上限 2.5
- 移动速度倍率 = min(1.2, 1.0 + 0.007 × (天数 − 1))
- 同时存活上限 = min(20, 8 + floor(天数 × 0.6))
- 远程枪手占比 = min(60%, 10% + 天数 × 2.9%)
- 大型怪占比 = min(30%, floor((天数 − 1) / 1.5) × 1.7%)

说明：第 7 天为一周节奏的关键压力点，第 14 天为双周挑战点，与成就「生存一周 / 生存两周」对齐。

### 10.3 为将来联机保留的最小架构预留

为降低将来接入联机时的改造量（对应 RK11），以下解耦在首版即应落地。除注明外均为零成本或低成本项，不额外增加首版功能。

| 预留项 | 要求 | 成本（工程侧已确认） |
|--------|------|----------------------|
| 游戏逻辑与渲染解耦 | 逻辑层不直接调用渲染 API，渲染从逻辑状态读取 | 零成本（与平台分层要求重合） |
| 游戏逻辑与输入解耦 | 输入映射为「意图」，逻辑消费意图而非原始按键事件 | 零成本（与平台分层要求重合） |
| 世界状态可序列化 | 方块、实体、玩家、时间均以可序列化数据结构表达，支撑存档与将来同步 | 零成本（复用存档契约） |
| 时间步进与帧率解耦 | 逻辑以固定时间步长推进、渲染插值，为服务器权威模拟预留 | 零成本（物理方案本已采用固定 60 Hz + 插值） |
| 世界改动单一入口与状态快照接缝 | 所有方块与实体改动经统一入口，世界状态可整体快照 | 低成本（各约 0.5%–1%） |
| 协议版本号占位 | 在存档与状态结构中预留版本字段 | 零成本 |

整体预留成本合计 **≤2%**，且不增加任何首版功能。

**工程侧验收口径**（对应附录 A7）：存在统一的「世界改动入口」接口，且单机可运行、不含联网代码。

说明：本表由主理人依据 `docs/architecture/technical-constraints.md` v0.2 第 6.5 节的工程结论回写，原「待与程基岩确认」项已全部确认，成本口径较设计侧初判下调（三项从「低成本」修正为「零成本」）。
