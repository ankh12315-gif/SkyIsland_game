## 2. 产品概述

### 2.1 一句话定位

用**基于 Java + LWJGL 自研体素游戏引擎，不依赖 Unity、Unreal 等完整商业游戏引擎**实现的《我的世界》式第一人称空岛生存游戏，核心差异化是**空岛 + 枪械战斗**。

本作为**单机生存**，联机为后续迭代规划（原决策 12 的 2–4 人合作已推迟，详见第 7 章），首版不实现任何联机功能。

### 2.2 设计支柱

设计支柱是判断一切设计取舍的最高依据。当两条需求冲突时，按支柱排序裁决。

| 编号 | 支柱 | 释义 | 对应决策 |
|------|------|------|----------|
| P1 | **虚空之上的生存张力** | 可活动空间有限、资源空间分离、坠落即死。所有系统须强化「脚下无地」的持续压迫感，禁止设计让玩家高枕无忧的无风险区域 | 决策 3、5、10、15、16 |
| P2 | **自造枪械的战斗节奏** | 玩家开局拥有基础自卫枪械，但持续弹药供应、更强枪械与完整武器体系必须依靠采集、远征与合成逐渐获得。战斗节奏围绕「采集—造弹—远征—再升级」形成闭环 | 决策 6、7、8 |
| P3 | **昼夜驱动的推进节奏** | 白天外出采集与建造，夜晚防守与战斗。昼夜是主循环的节拍器，而非纯视觉表现 | 决策 8、14 |
| P4 | **可扩展的体素基座** | 架构与内容分离，方块、枪械、怪物、配方均以数据驱动方式扩展，支撑长期迭代成正式作品 | 决策 1、4、17、20 |

> P2 口径说明（v0.3 修订）：v0.2 曾写「枪械本身是长期进度目标而非开局装备」，与「开局赠送手枪」冲突。本版明确：**开局拥有基础自卫枪械**（手枪 ×1），但**持续弹药供应、更强枪械与完整武器体系**仍须通过采集、远征与合成获得。开局手枪不构成对 P2 的削弱。

### 2.3 目标玩家画像

| 维度 | 描述 |
|------|------|
| 核心画像 | 喜爱《我的世界》空岛玩法、对体素沙盒有耐心、期待「从零建造」成就感的玩家 |
| 次要画像 | 喜爱轻量射击对抗、希望在沙盒里获得战斗压力的玩家 |
| 游玩时长 | 单次会话 30–90 分钟；单人长线存档 10 小时以上 |
| 平台 | Windows PC（键盘 + 鼠标） |
| 前置经验 | 熟悉第一人称操作与 WASD 键位；无需阅读教程即可上手（依赖通用键位习惯与即时提示） |
| 不覆盖人群 | 追求剧情与结局的玩家（本作无结局）；追求高拟真硬核射击的玩家（首版无后坐力/散布） |

### 2.4 与《我的世界》空岛玩法的差异化

| 维度 | 《我的世界》经典空岛 | 本作 | 差异价值 |
|------|----------------------|------|----------|
| 空间结构 | 单一小岛，靠刷怪掉资源 | 主岛 + 4 座资源小岛，资源空间分离 | 强制玩家在岛屿间移动，放大坠落风险与探索动力 |
| 战斗 | 近战 + 弓，战斗为次要系统 | 枪械为主，昼夜刷怪 + 会还击的远程枪手 | 战斗成为独立支柱，夜晚形成明确的压力峰值 |
| 资源循环 | 依赖刷石机与刷怪塔 | 矿物集中于资源小岛；核心资源岛设资源核心（少量缓慢再生） | 前期无软锁风险，枪械材料靠远征资源岛获得 |
| 成长曲线 | 无明确难度增长 | 威胁等级随天数分段递增，枪械进度与之对抗 | 提供「无结局」下的长期目标感 |
| 实现方式 | 官方/模组引擎 | 基于 Java + LWJGL 自研体素游戏引擎，不依赖 Unity、Unreal 等完整商业游戏引擎 | 技术自主，架构专为长期迭代设计 |

## 3. 玩法主循环

### 3.1 三层循环拆解

| 层级 | 时长 | 循环内容 | 玩家动机 | 优先级 |
|------|------|----------|----------|--------|
| 分钟级 | 30 秒–3 分钟 | 采集（挖方块/打怪）→ 合成（背包内直接合成）→ 建造/射击 → 返回安全区 | 资源即时反馈；即时生存决策 | 【MVP 必须】 |
| 小时级 | 20–60 分钟 | 白天远征资源岛采集矿物 → 合成弹药 → 夜晚防守增强的怪物 → 扩建主岛平台 | 枪械进度解锁；应对递增威胁 | 【MVP 必须】 |
| 长期级 | 数小时–数十小时 | 全岛屿探索完成 → 全枪械收集 → 建造大型工程 → 冲击挑战成就 | 建造成就；收集完整度；自我设定目标 | 【Alpha 必须】 |

### 3.2 分钟级循环（微观）

1. 决定目标：采集材料 / 建造 / 防守 / 远征。
2. 执行动作：使用左键挖掘或开枪，右键放置或瞄准。
3. 结算产出：方块掉落物自动飞向玩家并拾取（拾取半径 2 格）；怪物掉落材料直接进背包。
4. 合成转化：按 E 打开背包，在背包内直接选择配方合成。
5. 消费/再投入：消耗弹药，决定回小屋休整或继续推进。

循环设计目的：保证任意 3 分钟内都有一次「决策—执行—获得」的完整反馈，维持短周期节奏。

> 说明：饥饿消耗在本循环中**不属于 MVP**（见 5.3）；MVP 的分钟级循环以弹药消耗与生命管理为压力来源。

### 3.3 小时级循环（中观）

1. 清晨（黎明）：结算新一天，威胁等级按分段表提升。
2. 白天（约 11 分钟）：主岛补给（Alpha 含刷石机产石、农田收麦），随后远征资源小岛采矿。
3. 黄昏（约 1 分钟）：返回主岛，布置防御（放置方块掩体、备弹）。
4. 夜晚（约 7 分钟）：应对刷怪（Alpha 起含远程枪手），消耗弹药。
5. 深夜复盘：合成新弹药、修复防御工事、规划次日远征目标。

循环设计目的：以昼夜为节拍器，形成「扩张—收缩」的节奏张力。

> MVP 说明：刷石机与农田属 Alpha（见 5.7、10.2）；MVP 的白天补给以「开局小屋初始物资 + 石矿岛采集」为主。

### 3.4 长期级循环与内在目标设计（应对「无结局」）

由于本作无结局（决策 3），长期动力必须由内在目标补足。内在目标分三类。**本节全部内容为【Alpha 必须】；MVP 阶段不实现。**

#### 3.4.1 探索度【Alpha 必须】

| 目标 | 衡量方式 | 奖励反馈 |
|------|----------|----------|
| 岛屿探索 | 5 座岛屿全部到达并在其上采集过矿物，记为探索度 100% | HUD 显示探索度进度；达 100% 解锁成就「群岛旅人」 |
| 资源采集完整 | 记录已采集的资源种类（共 8 类可采材料） | 背包界面显示收集图鉴，未采集项显示剪影 |

> 说明：探索度依赖 5 座岛屿，MVP 只有 2 座（主岛 + 石矿岛），故 **MVP 阶段不实现探索度系统**。

#### 3.4.2 建造里程碑【Alpha 必须】

| 里程碑 | 达成条件 | 说明 |
|--------|----------|------|
| 扩岛工程 | 主岛平台面积扩展至 ≥ 48×48 | 玩家自主建造，系统仅记录并给成就 |
| 跨岛通路 | 建成至少 1 条连接主岛与资源岛的实体通道 | 用方块逐格相邻搭建而成；**不允许无邻接支撑的悬空放置**（见 5.2） |
| 防御工事 | 在主岛外围建成完整围墙（周长 ≥ 64 格的封闭结构） | 系统按方块连续性判定 |
| 扩建至 64×64 | 主岛平台扩展至 ≥ 64×64 | 长期建造目标 |

> 「跨岛通路」口径修订（v0.3）：v0.2 此处写「允许悬空放置」，与 5.2 冲突。本版统一为「方块必须与已有实体方块相邻；玩家仍可逐格向虚空延伸搭桥」。

### 4.6 资源核心与矿物再生【MVP 必须】

**设计背景**：v0.2 写「资源小岛矿物不耗尽」，与 5.2「挖掘会真实移除方块」冲突，且不给出再生机制。本版改为**有限矿脉 + 再生兜底**。

| 规格项 | 规则 |
|--------|------|
| 普通矿脉 | 正常挖空，不自动补充 |
| 资源核心 | 每个核心资源岛设 **1 个「资源核心」方块**：稳定 ID `skyisland:resource_core`，属**系统方块**（定义见 5.1.1），不计入玩家可用方块 |
| 不可破坏 | 资源核心**不可挖掘、不可被任何方式移除**（爆炸/环境均不适用） |
| 再生行为 | 核心按固定长周期，在指定范围内**缓慢再生少量对应矿石** |
| 再生速率约束 | 再生速度**远低于**正常远征采矿效率，防止站桩无限刷矿（详见下表说明） |
| 占用冲突 | 再生目标格被玩家方块占据时**跳过该格、顺延到下一个可用位置**，不得覆盖玩家方块 |
| 离线计算 | **不做离线计算**，仅游戏运行时累计 |

**核心参数表（MVP 只实现石矿岛 1 座）：**

| 岛 | 核心位置 | 刷新周期 | 单次刷新数量 | 刷新范围 | 是否离线计算 | 优先级 |
|----|----------|----------|--------------|----------|--------------|--------|
| 石矿岛 | 岛几何中心 (48, 0)，表面层 y = 64 下一格 | 180 秒 | 1 格 | 核心周围 5×5 水平、y ∈ [核心 y − 2, 核心 y + 1] | 否 | 【MVP 必须】 |
| 森林岛 | 岛几何中心 | 180 秒 | 1 格 | 同上 | 否 | 【Alpha 必须】 |
| 金属岛 | 岛几何中心 | 180 秒 | 1 格 | 同上 | 否 | 【Alpha 必须】 |
| 晶矿岛 | 岛几何中心 | 240 秒 | 1 格 | 同上 | 否 | 【Alpha 必须】 |

**再生速率对比（防止站桩刷矿）：**

| 项 | 速率 |
|----|------|
| 玩家远征采矿 | 约 20–40 格/分钟（空手平均 1.5–3 秒/格） |
| 核心再生（石矿岛） | 0.33 格/分钟（180 秒 1 格） |
| 比值 | 再生速率 ≤ 采矿速率的 **1/50** |

**三重防软锁（必须同时成立）：**
1. **核心不可破坏**：资源核心永不被移除，保证再生源永久存在。
2. **慢速再生**：核心持续补充少量矿石，避免矿物彻底枯竭。
3. **怪物掉落兜底**：夜间怪物掉落矿石/材料（见 5.5.6），保证远征受阻时进度仍可缓慢推进。

> MVP 范围：MVP 只实现**石矿岛 1 座岛的简单版本**（1 个核心、180 秒 1 格、无离线计算）。其余 3 岛及复杂再生为 Alpha。

#### 5.5.2 怪物 AI【MVP 必须】（MVP 近战怪 7 步行为）

MVP 只实现 **1 种近战怪**，行为固定为 7 步：

1. 检测玩家（视觉/距离）。
2. 玩家进入追击范围后追击。
3. 朝玩家**水平方向**移动。
4. 前方碰撞时尝试左右偏转。
5. 前方为虚空则停止或换方向（**不主动踏入虚空**）。
6. 接近玩家后攻击。
7. 无法到达时不做全地图寻路（允许卡住）。

**AI 技术复杂度边界（MVP 禁止项）：**

| 禁止项 | 说明 |
|--------|------|
| 动态寻路 | MVP 不做复杂动态 NavMesh / 大规模实时 A* |
| 跳跃寻路 | MVP 怪物不进行跳跃以跨越障碍 |
| 破坏方块寻路 | MVP 怪物不破坏方块以开辟路径 |

> 边界理由：体素世界允许玩家实时挖墙 / 搭桥 / 封路，MVP 不做复杂动态寻路；Alpha 起再加冲锋怪、远程枪手、大型怪与更完整寻路。
> 边界条件：**怪物不主动走进虚空**（第 5 步）；**怪物掉入虚空时立即移除，不掉落任何物品**。

## 9. MVP / Vertical Slice 范围

> 本章为 v0.3 新增，是本轮最重要的收敛产物。**核心原则：先做出一个真正好玩的 20–25 分钟核心循环，再扩充内容。**

### 9.1 核心验收一句话

> 玩家从开局小屋出生 → 能移动和挖方块 → 能放置方块并搭桥 → 到达一个资源岛 → 获得资源 → 合成弹药 → 天黑 → 怪物出现 → 玩家使用手枪战斗 → 成功活到第二天黎明（首轮完整循环目标时长 20–25 分钟，见 4.4）→ 游戏可以保存并再次读取。

### 9.2 MVP 内容清单（严格按此，不得扩大）

| 类别 | MVP 内容 | 说明 |
|------|----------|------|
| 世界 | 主岛 32×32、**1 座资源岛（石矿岛，坐标 (48,0)，14×14）**、虚空、开局房子 | 其余 3 座岛 → Alpha |
| 方块 | **13 种玩家常规方块**：草方块、泥土、石头、圆石、原木、木板、树叶、玻璃、铁矿石、煤炭矿石、沙子、火把、木门；另含 **1 种系统方块** `skyisland:resource_core`（见 5.1.1，不计入玩家可用方块） | 数量高于「6–8」的理由见 9.3；系统方块单独计数 |

### 9.3 MVP 方块数量说明（13 种玩家常规方块的理由）

MVP 方块数量（13 种）高于初始提示的「6–8」，理由是**闭环必需**：
- 小屋需要**玻璃**（窗）与**木门**（门）——否则开局小屋无法按设计建成可辨识的庇护所。
- 火药（R06）需要**煤炭**与**沙子**——否则 MVP 无法合成弹药，弹药闭环断裂。
- 弹药（R11）需要**铁**（铁矿石→铁锭）——否则核心循环无法闭合。
- 因此 13 种为**能跑通核心循环的最小方块集**，不得再削减。
- **另有 1 种系统方块** `skyisland:resource_core`（资源核心，定义见 5.1.1）：它必须进入 Block Registry 并被存档识别，但不可破坏、不可拾取、不可放置、不进入玩家背包，因此**不计入玩家可用方块**。
- MVP 的完整方块口径为：**13 种玩家常规方块 ＋ 1 种系统方块**。

### 9.4 MVP 明确不实现

完整饥饿、4 把枪、4 种怪、其余 3 座岛、成就系统、完整农业、复杂资源再生、完整音效、大量粒子、联机、高级设置、复杂 AI、枪械后坐力、配件、天气、沙子重力、铜/金/晶体、树苗、石砖。

### 9.5 MVP 判定准则（第 13 章原则的落地）

判断一个功能是否进入 MVP，只问：

> 如果删除这个功能，「挖 → 搭桥 → 远征 → 获得资源 → 做弹药 → 夜晚打怪 → 活到第二天黎明」还能不能成立？
> - 能成立 → 优先降到 Alpha；
> - 不能成立 → 才进入 MVP。

## 12. 产品级技术约束

> 本章为 v0.3 新增，只写**产品级技术约束与口径**，不写完整技术设计。完整技术设计见 `docs/architecture/technical-constraints.md` 及后续 `docs/TECH_DESIGN.md`。

### 12.1 引擎与平台口径

- 实现方式统一表述为：**基于 Java + LWJGL 自研体素游戏引擎，不依赖 Unity、Unreal 等完整商业游戏引擎**。
- LWJGL 自带 native bindings，「纯 Java」表述不严谨，全文废止该说法（除修订记录与变更日志的历史引用）。
- 图形 API 目标 OpenGL 3.3 Core；平台优先 Windows x64。

### 12.2 射击命中判定（v0.3 修正）

- v0.2 写「怪物优先于方块」为**错误规则，予以废止**。
- 正确规则：**同一射线同时计算方块命中与实体命中，取沿射线距离最近的合法碰撞结果**。
  - 不允许隔着墙命中怪物；
  - 最近命中为方块时记为方块命中（溅射粒子）；
  - 仅当最近命中为实体时才结算伤害。

### 12.3 存档规格

| 项 | 规则 |
|----|------|
| 存档版本 | 所有存档增加 `saveVersion`（首版 = 1）；格式变更时必须能判断版本、迁移、或提示不兼容 |
| 稳定 ID | **禁止用 enum ordinal 或数组下标作为永久存档 ID**；使用稳定字符串 ID，如 `skyisland:stone`、`skyisland:iron_ore`、`skyisland:pistol` |
| MVP 必存字段 | 世界 Seed、玩家位置、生命、背包、快捷栏、世界时间、天数、被修改过的方块、`saveVersion`、岛屿生成版本 |
| 崩溃时防护 | 原子写入（写临时文件 → 落盘 → 原子改名）+ 保留上一版 `.bak` + CRC32 校验；读取失败时回退 `.bak` 并提示 |
| 退出时自动保存 | 是 |
| 手动保存 | 支持；Esc 暂停菜单提供「保存」；另有黎明结算自动保存 |
| 暂停时世界 | 是（Esc 暂停菜单打开时世界时间与模拟暂停） |
| 界面打开时世界 | 背包/合成界面打开时**世界继续运行**（保持 P1 张力）；鼠标显示光标且不再控制视角，关闭后恢复（见 6.2） |

### 12.4 数据驱动原则

- Block、Item、Gun、Ammo、Recipe、Monster stats、Threat Level、Resource distribution **尽量做配置数据而非硬编码**。
- 具体 JSON schema 放到后续 `TECH_DESIGN.md`；本 PRD 只写原则与默认值。

### 12.5 性能验收基准

**基准机器（v0.3.1 重新实测，2026-09-19）：**

| 项 | 实测值 | 采集来源 |
|----|--------|----------|
| 机型 | LENOVO 83AL（笔记本电脑） | Win32_ComputerSystem |
| CPU | 13th Gen Intel(R) Core(TM) i5-13500H，12 物理核 / 16 逻辑线程，基准 2.6 GHz | Win32_Processor |
| 内存 | 15 730 MB（16891371520 字节，约 15.7 GB） | Win32_ComputerSystem |
| 操作系统 | Microsoft Windows 11 家庭版 中文版，版本 10.0.26200（Build 26200），64 位 | Win32_OperatingSystem |
| 显卡（唯一物理 GPU） | **Intel(R) Iris(R) Xe Graphics**（VideoProcessor：Intel(R) Iris(R) Xe Graphics Family；共享显存约 2 GB） | Win32_VideoController |
| 显卡驱动 | **32.0.101.5542**（驱动日期 2024-06-08） | Win32_VideoController |
| **独立显卡** | **无。** 全量枚举显示适配器后，除 Intel Iris Xe 外仅有 3 个虚拟显示适配器（Todesk Virtual Display Adapter、GameViewer Virtual Display Adapter、USB Mobile Monitor Virtual Display），均为软件虚拟显示器，**不作为渲染基线** | Win32_VideoController 全量枚举 |

**关于独显的明确结论（必答项）：**
- 本机**不存在独立显卡**，因此不存在「游戏实际使用哪张 GPU」的选择问题：渲染一律由 **Intel Iris Xe** 完成。
- **集显基准即本项目唯一的最低性能测试基准**，不另设独显基准。
- 若将来在带独显的机器上测试，必须**单独记录为「独显基准」**，且**不得替代集显基准**作为门禁判定依据。

**测试条件（固定）：** 1920×1080 渲染分辨率、Windows x64、Release 构建（fat jar）、**VSync 关闭**、默认视距 6 区块、标准测试世界（MVP 阶段为主岛 + 石矿岛）、正常怪物数量（不超过当前 Threat Level 上限）、持续测试 **MVP ≥ 5 分钟 / Alpha 与 RC ≥ 10 分钟**。

> 阶段性口径差异：M0 尚无世界与视距概念，采用 **1280×720 窗口 + 空场景** 作为技术验证口径；**1920×1080 + 视距 6 区块**的性能门禁自 **M1** 起生效。
> 高 DPI 面板（本机 2880×1800）下必须区分**窗口尺寸**与**帧缓冲尺寸**，性能统计以帧缓冲实际像素为准。

**判定口径：** 测试时长内**第 95 百分位帧时间 ≤ 16.7 ms**，且**不得出现 > 50 ms 的卡顿**（GC 与渲染尖峰均计入）。

**硬约束：** 「视距 6 区块 + 集成显卡 60 FPS」为 **M1 门禁**。禁止只写「60 FPS」而不给基准环境。

## 13. 开发优先级原则

> 本章为 v0.3 新增，作为后续范围裁决依据。任何新需求是否进入 MVP，一律以本章为准。

判断一个功能是否进入 MVP，只问：

> **如果删除这个功能，「挖 → 搭桥 → 远征 → 获得资源 → 做弹药 → 夜晚打怪 → 活到第二天黎明」还能不能成立？**
> - **能成立 → 优先降到 Alpha；**
> - **不能成立 → 才进入 MVP。**

推论：
- 不要因为 v0.2 标注了「首版必须」就机械保留；三档优先级（MVP / Alpha / 后续迭代）以本原则重判。
- 先做出一个真正好玩的 20–25 分钟核心循环，再扩充内容。
- 核心循环不好玩时，优先修改玩法与手感，禁止以扩充内容掩盖（见 M3-GATE 门禁规则）。

### 14.3 为将来联机保留的最小架构预留

为降低将来接入联机时的改造量（对应 RK10），以下解耦在首版即应落地。除注明外均为零成本或低成本项，不额外增加首版功能。

| 预留项 | 要求 | 成本（工程侧已确认） |
|--------|------|----------------------|
| 游戏逻辑与渲染解耦 | 逻辑层不直接调用渲染 API，渲染从逻辑状态读取 | 零成本（与平台分层要求重合） |
| 游戏逻辑与输入解耦 | 输入映射为「意图」，逻辑消费意图而非原始按键事件 | 零成本（与平台分层要求重合） |
| 世界状态可序列化 | 方块、实体、玩家、时间均以可序列化数据结构表达，支撑存档与将来同步 | 零成本（复用存档契约） |
| 时间步进与帧率解耦 | 逻辑以固定时间步长推进、渲染插值，为服务器权威模拟预留 | 零成本（物理方案本已采用固定 60 Hz + 插值） |
| 世界改动单一入口与状态快照接缝 | 所有方块与实体改动经统一入口，世界状态可整体快照 | 低成本（各约 0.5%–1%） |
| 协议版本号占位 | 在存档与状态结构中预留版本字段 | 零成本 |

整体预留成本合计 **≤2%**，且不增加任何首版功能。

**工程侧验收口径**：存在统一的「世界改动入口」接口，且单机可运行、不含联网代码。
