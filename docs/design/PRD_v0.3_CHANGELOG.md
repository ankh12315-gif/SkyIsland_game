## MVP 降级项

从 v0.2 的【首版必须】降级/拆分出的内容（按第 13 章原则判定：删除后核心循环仍成立者优先降级）。

| 序号 | 降级项 | 从 | 到 | 降级理由 |
|------|--------|----|----|----------|
| D01 | 3 座资源岛（森林岛、金属岛、晶矿岛） | 首版必须 | 【Alpha 必须】 | MVP 只需 1 座资源岛即可闭合「远征→资源→弹药」 |
| D02 | 3 把枪（冲锋枪、步枪、霰弹枪） | 首版必须 | 【Alpha 必须】 | MVP 只用 1 把手枪即可验证枪战支柱 |
| D03 | 2 种弹药（步枪弹、霰弹） | 首版必须 | 【Alpha 必须】 | 随枪械降级 |
| D04 | 3 种怪（冲锋怪、远程枪手、大型怪） | 首版必须 | 【Alpha 必须】 | MVP 只需 1 种近战怪验证夜战节奏 |
| D05 | 完整饥饿系统 | 首版必须 | 【Alpha 必须】（MVP 不启用） | 饥饿压过探索与战斗；MVP 无饥饿保证核心循环纯净 |
| D06 | 成就系统（11 项） | 首版必须 | 【Alpha 必须】 | 成就非核心循环必需 |
| D07 | 完整农业（小麦种植/收割/补种闭环） | 首版必须 | 【Alpha 必须】 | MVP 无饥饿，农业无落点 |
| D08 | 刷石机 + 小农田（内部设施） | 首版必须 | 【Alpha 必须】 | MVP 只保留小屋本体 + 初始物资 |
| D09 | 资源再生（全岛） | 首版必须 | 【Alpha 必须】（MVP 只做石矿岛简化版） | MVP 先验证单岛再生闭环 |
| D10 | 威胁等级 TL2–TL4 | 首版必须 | 【Alpha 必须】（MVP 恒为 TL1） | MVP 无难度递增需求 |
| D11 | 探索度（5 岛 100%） | 首版必须 | 【Alpha 必须】 | 依赖 5 座岛，MVP 只有 2 座 |
| D12 | 建造里程碑（扩岛/跨岛/防御/64×64） | 首版必须 | 【Alpha 必须】 | 长期目标，非核心循环必需 |
| D13 | 沙子重力 | 首版必须 | 【Alpha 必须】（MVP 保留沙子方块但无重力） | 火药原料保留沙子；重力为表现层 |
| D14 | 铜矿石/金矿石/晶体矿石方块 | 首版必须 | 【Alpha 必须】 | 随进阶枪械降级 |
| D15 | R04 铜锭、R05 金锭 | 首版必须 | 【Alpha 必须】 | 随进阶枪械降级；R05 另有死道具问题（见 C14） |
| D16 | R09 木门、R10 面包、R12 步枪弹、R13 霰弹、R14–R17 枪械、R18 石砖（共 11 条） | 首版必须 | 【Alpha 必须】 | MVP 只保留 7 条闭环配方 |
| D17 | 树苗（方块/掉落/种植） | 首版必须 | MVP 移除 / 种植【Alpha 必须】 | 树叶改为不掉落树苗 |
| D18 | 石砖（方块） | 首版必须 | 【Alpha 必须】 | 见 C12 |
| D19 | 饥饿条、成就弹窗、探索度 HUD | 首版必须 | 【Alpha 必须】 | 随系统降级 |
| D20 | 音乐音量设置项 | 首版必须 | 【Alpha 必须】（主音量/音效音量保留 MVP） | MVP 用占位音效 |
| D21 | 面包 ×6、小麦种 ×4（初始物资） | 首版必须 | MVP 移除 | MVP 无饥饿、无农业 |
| D22 | 局域网联机 | 首版必须（v0.1） | 【后续迭代】（v0.2 已移出，v0.3 保持） | 重大范围变更 |

> 说明：以上降级不改变 v0.2 已确认的玩法结构，仅重新划定交付阶段；所有降级项均在 v0.3 中明确标注归属阶段。

## 新增规则

| 序号 | 新增规则 | 所在章节 | 要点 |
|------|----------|----------|------|
| N01 | 资源核心与矿物再生 | 4.6 | 每核心资源岛 1 个不可破坏核心；长周期缓慢再生；占用顺延不覆盖玩家方块；不做离线计算 |
| N02 | 三重防软锁 | 4.6 | ① 核心不可破坏 ② 慢速再生 ③ 怪物掉落兜底 |
| N03 | 再生速率约束 | 4.6 | 再生速率 ≤ 采矿速率 1/50，防止站桩无限刷矿 |
| N04 | lastSafePosition 与虚空死亡掉落回收 | 5.3.1 | 定义/更新时机（落地稳定 ≥0.5 秒）；虚空死亡掉落落在 lastSafePosition 附近，严禁入虚空；普通死亡不变 |
| N05 | 重生点规则 | 5.3.1 | 固定点 (0,64,0)；不合法则 y=64 平面螺旋搜索（半径 ≤16）；仍无则生成 1 格临时木质地台；小屋拆除不影响 |
| N06 | 放置邻接支撑规则 | 5.2 / 4.5 / 3.4.2 | 必须与已有实体方块相邻；保留 reach 5.0、y∈[1,127]、不可放入碰撞体 |
| N07 | 分段 Threat Level 数据驱动 | 5.5.4 | TL1–TL6 分段表；JSON/配置驱动；PRD 只定义字段与默认值 |
| N08 | 怪物 AI 7 步行为 + 技术复杂度边界 | 5.5.2 | MVP 近战怪固定 7 步；禁止动态/跳跃/破坏方块寻路 |
| N09 | Hitscan 最近命中修正 | 5.4.3 / 12.2 | 方块与实体同射线取最近；不允许隔墙命中 |
| N10 | 存档版本 saveVersion | 12.3 | 首版 = 1；支持判断/迁移/不兼容提示 |
| N11 | 稳定字符串 ID | 12.3 / 5.1 / 5.4 | 禁止 enum ordinal / 数组下标；如 `skyisland:stone` |
| N12 | 存档原子写入与容错 | 12.3 | 临时文件 → 落盘 → 原子改名 + .bak + CRC32；读取失败回退并提示 |
| N13 | 自动保存 / 手动保存 / 暂停规则 | 12.3 | 退出自动保存；Esc 提供手动保存；黎明结算保存；暂停时世界暂停 |
| N14 | 界面打开时世界继续运行 | 6.2 / 12.3 | 背包/合成打开时世界运行；鼠标显示光标；被攻击红闪 + 音效；生命 ≤0 强制关闭进死亡流程 |
| N15 | 首次进入提示 | 6.7 | 「WASD 移动，左键挖掘，右键放置」，3 秒淡出，仅首次 |
| N16 | 背包满提示规则 | 5.2 / 6.7 | 掉落物留地 5 分钟；拾取失败提示「背包已满」，同类提示 5 秒内不重复；挖掘仍可进行 |
| N17 | 怪物坠入虚空处理 | 5.5.2 | 立即移除，不掉落任何物品 |
| N18 | 掉落物坠入虚空处理 | 4.5 / 5.2 | y < -8 立即销毁 |
| N19 | 木门规则 | 5.1 | 占 1 格、可右键开关、关闭阻挡/开启无碰撞；双格门为 Alpha 可选 |
| N20 | 火把固定径向衰减 | 4.4 | 半径 6 格线性衰减，不做全局光照传播 |
| N21 | 性能验收基准环境 | 12.5 | 明确 CPU/内存/OS/GPU/测试条件/判定口径；集成显卡为硬约束 |
| N22 | 三档优先级定义 | 1.2 | MVP = M0–M3；Alpha = M4；首版 = M0–M5 |
| N23 | M3-GATE 垂直切片门禁 | 11 章 | 7 条问题强制逐条回答；门禁规则：核心循环不好玩禁止以扩充内容掩盖 |
| N24 | 开发优先级原则 | 13 章 | 「删除该功能后核心循环是否仍成立」判定 |
| N25 | 数据驱动原则 | 12.4 | Block/Item/Gun/Ammo/Recipe/Monster/TL/Resource 尽量配置化 |

## 一、本轮四项微修补

### R1 · MVP 时长口径修正（20–25 分钟）

| 项 | 内容 |
|----|------|
| 问题 | v0.3 全文以「10–20 分钟」描述 MVP 垂直切片时长，与 4.4 节「每 20 分钟一个昼夜循环」不自洽——玩家若只能玩 10–20 分钟，就无法在首轮体验完整昼夜（含夜战），而夜战正是 MVP 核心循环的收口环节 |
| 改法 | 全文口径统一为 **20–25 分钟**；完成条件由「活到第二天」改为 **「活到第二天黎明」**（必须完整穿过一次夜晚，才算走通昼夜闭环） |
| 命中位置 | 全文 4 处时长表述、2 处完成条件、9.1 验收句、M3 通过标准、M3-GATE 第 6 问 |
| 附加规则 | 4.4 节新增两条：①「新世界默认从黎明开始」；②「首轮 Vertical Slice 时长口径为 20–25 分钟，**不为了迎合更短的时长目标而压缩 20 分钟昼夜设计**」 |
| 判定理由 | 时长是**验收口径**，昼夜长度是**设计参数**。二者冲突时应改口径而非改设计参数——否则等于用验收标准倒逼玩法降级 |

### R2 · 新增系统方块 `skyisland:resource_core`

| 项 | 内容 |
|----|------|
| 问题 | 4.6 节引入了「资源核心」（不可破坏的再生锚点），但 5.1 方块表、8 章数据表、9 章验收清单中**均无该方块的登记**。工程侧无法把它当作一类方块实现：它既不是玩家方块（不可挖、不可放置、不入背包、无掉落），也不是空气/占位符（需要渲染、需要碰撞、需要存档） |
| 改法 | 新增 **5.1.1 系统方块**小节，定义 `skyisland:resource_core`；5.1 方块计数改口径为 **「13 种玩家常规方块 ＋ 1 种系统方块」**；第 8 章方块数据表补行、9.2/9.3 验收章节标题同步 |
| 契约（写死） | 稳定字符串 ID `skyisland:resource_core`；**不可破坏 / 不可拾取 / 不可放置 / 不进入背包 / 无掉落物**；参与渲染与碰撞；存档中按稳定 ID 序列化，随 saveVersion 演进 |
| 计数修正 | MVP 方块：**玩家常规 13 种**（v0.3 口径）+ **系统 1 种**；不把系统方块计入玩家可见方块枚举，避免与「MVP 13 种」的既有引用冲突 |
| 判定理由 | 「不可破坏」是一种**行为契约**，不是「不存在」。凡是需要渲染 + 碰撞 + 存档的实体，必须在数据层显式登记，否则它会退化成魔法字符串散落在代码各处 |

### R4 · 12.5 性能验收基准——由实测硬件重写

| 项 | 内容 |
|----|------|
| 问题 | v0.3 的 12.5 节中，性能基准机的 GPU 字段是**估计值**，独显有无未探明（见 v0.3 CHANGELOG 的 O03）。性能验收基准若建立在猜测的硬件上，M1 的 60 FPS 判定就没有意义 |
| 改法 | **不猜，直接采**。对本机做硬件枚举，用真实读数重写 12.5 全节 |
| 实测结论 | 本机 **无独立显卡**。系统中可见的显示适配器中，三个为虚拟显示器（Todesk / GameViewer / USB Mobile Monitor），唯一真实渲染设备为 **Intel Iris Xe Graphics**（驱动 32.0.101.5542） |
| 这直接改变了基准的含义 | 不存在「独显档位可以放宽」的退路——**Iris Xe 是唯一渲染目标，也即唯一最低性能基准**。所有 M1/M2/M3 性能判定都按集显标准执行 |
| 实测录入项 | 机型 LENOVO 83AL；CPU i5-13500H（12 核 16 线程）；内存 15.7 GB；OS Windows 11 Home Build 26200；面板 2880×1800 @120Hz；GL Renderer 字段留空，**标注「待 M0 实测回填」** |
