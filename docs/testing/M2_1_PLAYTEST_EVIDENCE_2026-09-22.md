## 3. 两条缺陷的日志证据

### D9 —— 枪口火光生在相机原点（「刺眼」）

**这条不需要日志，静态可证**：`CombatController.java:253` 把射线起点 `origin` 定为 `player.eyePosition()`，
`:266` 把这三个分量当 `muzzleX/Y/Z` 传给监听器，`SkyIslandGame.java:327` 原样交给 `spawnMuzzleFlash` ——
于是 0.16 格的闪光立方体中心与相机重合，而特效 pass 是**关掉面剔除**的（`CombatFxRenderer.java:307`，
注释写明是为了「绕序写反时不至于完全看不见」），所以玩家看到的是内壁。

本局的**间接旁证**：`gun_fire=12`。每一次开火都在相机内部生成一片近白 × alpha 0.90 的遮挡，共 12 次。

### D10 —— F4 刷怪落点在半空（「找不到了」）

三行证据即闭环：

1. **落点在半空**：`01:19:39` 生成于 `(-8.50, **70.00**, -12.50)`。同世界的玩家地面高度是 `64.00`
   （见 `01:19:52` 的落点与 `01:20:30` 的重生点），即**高出地表约 6 格**。
2. **玩家当时站在高处**：`01:20:25` 的进度行 `Player(-9.03, **71.00**, -5.82 vy=0.00 onGround=true)`，
   同帧 `放置=6` —— 玩家自己搭了台子，脚下比地表高约 7 格。
3. **怪一只都没丢**：`alive=2 / spawned=2 / removed=0`。所以「找不到」= **到不了、看不见**，
   **不是**「被移除 / 没生成 / 没渲染」。

机制：`debugSpawnMonster()` 在看天空（射线无命中）时取 `y = player.position().y`，
随后调用 `player.findNearestStandable(world, x, y, z, 3)`。但该函数**只沿同一 y 平面横向螺旋**
（它自己的 javadoc 就写着「沿同一 y 平面」），**不做垂直搜索** → 在 y=70 处找不到可站立点 → 返回 null →
回退保留 y=70 → 怪从半空自由落体到地表。而 `MeleeMonster` **不跳、不寻路**（设计如此，见其类 javadoc 第 7 步），
于是它停在塔底，玩家在自己搭的高台上无论怎么转头都看不到。

**顺带排除的一条误判**：实体 pass 是**接上的**（`Renderer.java:144` 调 `entityRenderer.render(...)`），
不是「没渲染」。这条要写下来，因为「找不到」的第一反应往往是怀疑渲染管线。

## 4. 这份日志当时**证明不了**什么，以及后来被推翻的推理

> **本节经一次大幅修订，保留修订史**。初版结论是「5 次受伤无法归因，因此『怪咬死玩家』立不住」。
> 后来把 `Player.hurt(...)` 的调用点逐个查清（4.1），该结论被**推翻**：5 次受伤**全部**是近战咬击，
> 怪确实把玩家咬死了。保留这段，是因为**推理链错在哪一步**比结论本身更值得记下来。

### 4.1 伤害来源：曾经不可归因，现已归因（结论与初版**相反**）

初版声称「坠落伤害同样走 `hurt()`，因此与咬击无法区分」。这个前提是**假设**的，查证后不成立：

- **`Player.hurt(...)` 在整个 `src/main` 里只有一个调用点**：`MeleeMonster.java:175` 的咬击。
  （`CombatController.java:271` 的 `target.hurt(damage)` 是 `Entity.hurt`，打的是怪物，不是玩家。）
- 坠落路径 `Player.java:766-769` **只算、只打日志、只存进 `lastFallDamage`，从不调用 `hurt()`**
  → **当前版本坠落完全不掉血**（见 4.4，这是一条 PRD 强制项缺失）。
- 虚空致死走 `die()`，不经过 `hurt()`。

因此本局的 `player_hurt=5` **只能**是近战咬击。`ATTACK_DAMAGE = 4`、`MAX_HEALTH = 20`：
**5 × 4 = 20，恰好致命。**

### 4.2 为什么这 5 咬能发生在玩家于 y=71 期间——近战判定**不含垂直分量**

初版还把「连咬 5 次要 ≥ 4 s，而 y=71 到死亡只有 2.4 s」当作反证。这个反证**也不成立**，
因为攻击判定里**根本没有高度**（`MeleeMonster.java:154-169`）：

```
double dx = player.position().x - position.x;
double dz = player.position().z - position.z;
double horizontal = Math.hypot(dx, dz);   // 只有水平分量
...
chasing = horizontal <= CHASE_RANGE;      // 24.0
if (horizontal <= ATTACK_RANGE) {         // 1.6 —— 判定中没有任何 y 项
    player.hurt(world, ATTACK_DAMAGE, Player.DamageCause.MELEE);
```

怪站在塔底（水平距离 ≈ 0.2 格）就能咬到站在 7 格高处台上的玩家。
`ATTACK_RANGE` 的 javadoc 只按「碰撞箱半宽 0.3 + 玩家半宽 0.3 + 容差」推导，是**纯水平口径** ——
遗漏垂直分量的来源就在这里。这一条同时解释了玩家「看不见它却一直掉血」的体感。

> **所以最初那句判断才是对的**：怪一直在正常工作，并且**把玩家咬死了**。
> 本轮已加的伤害归因日志（`Player.DamageCause`）让下一次试玩可以直接从日志读到这一行，不必再推。

### 4.4 顺带查到：一条 PRD【MVP 必须】项缺失，以及**测试为什么没拦住它**

`Player.fallDamageFor()` 的公式与 `PRD_v0.3.2.md:438`【MVP 必须】逐字一致，
但它**算完不施加**（`Player.java:766-769`）。更要紧的是测试侧：

`FallDamageTest` 的 8 个用例方法名依次是 `fallingThreeBlocksDealsNoDamage` /
`fallingFourBlocksDealsOneDamage` / `fallingFiveBlocksDealsTwoDamage` / `damageIsSettledOnlyOnLanding`……
—— **名字在描述行为，断言体却只读 `lastFallDamage()` 这个中间变量**；
整个文件里 `health` 与 `hurt` 出现 **0 次**。
于是「坠落 4 格造成 1 点伤害」这条，在**玩家生命纹丝不动**的情况下照样全绿。

> 这是那条判据的又一形态：**断言名断言语义、断言体测中间变量**。
