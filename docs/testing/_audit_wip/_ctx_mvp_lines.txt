935: ### 9.3 MVP 方块数量说明（13 种玩家常规方块的理由）
936: 
937: MVP 方块数量（13 种）高于初始提示的「6–8」，理由是**闭环必需**：
938: - 小屋需要**玻璃**（窗）与**木门**（门）——否则开局小屋无法按设计建成可辨识的庇护所。
939: - 火药（R06）需要**煤炭**与**沙子**——否则 MVP 无法合成弹药，弹药闭环断裂。
940: - 弹药（R11）需要**铁**（铁矿石→铁锭）——否则核心循环无法闭合。
941: - 因此 13 种为**能跑通核心循环的最小方块集**，不得再削减。
942: - **另有 1 种系统方块** `skyisland:resource_core`（资源核心，定义见 5.1.1）：它必须进入 Block Registry 并被存档识别，但不可破坏、不可拾取、不可放置、不进入玩家背包，因此**不计入玩家可用方块**。
943: - MVP 的完整方块口径为：**13 种玩家常规方块 ＋ 1 种系统方块**。
944: 
945: ### 9.4 MVP 明确不实现
946: 
947: 完整饥饿、4 把枪、4 种怪、其余 3 座岛、成就系统、完整农业、复杂资源再生、完整音效、大量粒子、联机、高级设置、复杂 AI、枪械后坐力、配件、天气、沙子重力、铜/金/晶体、树苗、石砖。

949: ### 9.5 MVP 判定准则（第 13 章原则的落地）
950: 
951: 判断一个功能是否进入 MVP，只问：
952: 
953: > 如果删除这个功能，「挖 → 搭桥 → 远征 → 获得资源 → 做弹药 → 夜晚打怪 → 活到第二天黎明」还能不能成立？
954: > - 能成立 → 优先降到 Alpha；
955: > - 不能成立 → 才进入 MVP。

1175: ## 13. 开发优先级原则
1176: 
1177: > 本章为 v0.3 新增，作为后续范围裁决依据。任何新需求是否进入 MVP，一律以本章为准。
1178: 
1179: 判断一个功能是否进入 MVP，只问：
1180: 
1181: > **如果删除这个功能，「挖 → 搭桥 → 远征 → 获得资源 → 做弹药 → 夜晚打怪 → 活到第二天黎明」还能不能成立？**
1182: > - **能成立 → 优先降到 Alpha；**
1183: > - **不能成立 → 才进入 MVP。**
1184: 
1185: 推论：
1186: - 不要因为 v0.2 标注了「首版必须」就机械保留；三档优先级（MVP / Alpha / 后续迭代）以本原则重判。
1187: - 先做出一个真正好玩的 20–25 分钟核心循环，再扩充内容。
1188: - 核心循环不好玩时，优先修改玩法与手感，禁止以扩充内容掩盖（见 M3-GATE 门禁规则）。
