## 1. 编号规则

| 项 | 规则 |
|----|------|
| 编号格式 | `MVP-<系统>-<三位序号>`，如 `MVP-WORLD-001` |
| 系统前缀 | LOOP 循环 / WORLD 世界·岛屿·昼夜·虚空·资源核心·Seed / BLOCK 方块·地形 / MINE 挖掘·放置 / SURV 生存·生命·死亡·重生·移动 / COMBAT 枪械·弹药·射击 / MOB 怪物·AI·刷怪·威胁等级·掉落 / ITEM 背包·物品·合成 / HUT 开局小屋·初始物资 / HUD HUD 元素 / UI 界面（背包·合成·主菜单）/ SET 设置项 / KEY 默认键位 / TEXT 中文文案 / SAVE 存档 / PERF 性能与技术约束 / GATE 里程碑通过标准 / SCOPE 内容量口径与 MVP 明确不实现 |
| 原子性 | 一条 Requirement = 一个可独立回答「是 / 否」的产品行为。宁可拆，不合并 |
| 「PRD 章节」列 | PRD v0.3.1 的章节号；里程碑条目写 `11 / M1`、`11 / M3` 等 |
| 「PRD 行号」列 | PRD_v0.3.1.md 的行号，用于精确定位原文 |
| 「原计划阶段」列 | **PRD 规定的**计划阶段（M0 / M1 / M2 / M3；PRD §1.2：【MVP 必须】对应 M0–M3）。判定依据：PRD 第 9.2 节 MVP 内容清单 + 第 11 章各里程碑「交付内容」。PRD 未明示的，按第 11 章交付内容就近判定，并在备注写明依据 |
| **不含实现状态列** | 按分工，实现状态与技术债由 engineering-lead 从代码侧提供；本文只给 PRD 侧事实（章节 / 行号 / 原文 / 系统 / 要求 / 阶段） |
| 未修改 PRD | 全文未改动 `PRD_v0.3.1.md` 任何一个字 |

## 6. 给 quality-lead 的重点核查提示（本审计认为最可能成为 GAP 的条目）

1. **MVP-MINE-005/006/007/008**（破坏反馈与破坏特效）：已知的"未实现且未登记"先例。视觉已补，**音效与 8–12 粒子仍未做（T-8.9）**，且粒子数量在技术文档里被写成 3–5（DRIFT-A-01）。**只要音频后端没接入，这四条就不可能全绿。**
2. **MVP-SET-002 / 005 / 008 / 011**（视距 / 死亡掉落 / 界面语言 / 亮度）：PRD 11 项 MVP 设置项中这 4 项在 M1.5 无实现、技术文档也无条目，是最典型的"没人提就不存在"。
3. **MVP-TEXT-* 与 MVP-HUD-008**（中文文案 / 枪械中文名）：受 ASCII 点阵字模限制，**整组在技术上不可兑现**（DRIFT-B-04），需用户裁决口径后再判定。
4. **MVP-UI-022 / MVP-SAVE-020**（「继续游戏」入口 / 暂停菜单独立「保存」项）：M1.5 只做到近似物，可能判 PARTIAL。
5. **MVP-KEY-008 潜行**：PRD 只给键位不给效果，M1.5 只建键位无消费方（`Action.CROUCH` → M2），**"MVP 必须"的潜行是否算满足需裁决**。
6. **MVP-MOB-019/020、MVP-MOB-027/028、MVP-WORLD-033～040**（刷怪选点约束、怪物掉落表、资源核心再生算法）：技术文档完全没有条目 → 实现时最容易凭感觉写、验收时最容易漏。
7. **MVP-HUT-001～007**（开局小屋 7 项结构规格）：M3 才交付，技术文档无条目，且含"南面留 1 处未封顶"这种极易被当成 bug 修掉的刻意设计。
8. **MVP-WORLD-026**（虚空可见性：向下即见天空/雾、虚空底部深色）：纯表现层，按 §V′.5 需要像素级取证，最容易被"代码看起来对"顶替。
