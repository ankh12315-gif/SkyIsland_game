02

里程碑时间轴

每个里程碑都必须通过自己的「通过标准」才能进下一阶段。M1.5 / M2.1 / M2.2 是 PRD 之外 实际发生的增补里程碑 —— 它们不在原始计划里，却占了目前一半以上的工作量，这件事本身就值得记一笔。

M0

Technical Spike

MVP 必须 CLOSED
交付内容

Maven 项目结构 · Java · LWJGL · GLFW Window · OpenGL Context · Input · Game Loop · FPS。只做技术验证，不含玩法。

通过标准
  • mvn package 无错误产出可运行产物
  • 启动后打开 1280×720 窗口并创建 OpenGL 3.3 Core 上下文
  • 主循环稳定运行且 FPS ≥ 60
  • 键鼠输入可被正确读取并打印
  • 窗口可正常关闭且无残留进程
  • 在目标 JDK 下实测 LWJGL 启动与告警并记录
结论：构建链（JDK 25 + Maven 3.9.9 + LWJGL 3.4.3）打通；GL/GLFW 环境事实实测； 发现并修正了一个测量仪器缺陷 —— 这件事后来反复证明它比"跑通构建"更值钱。

M1

Voxel Sandbox

MVP 必须 PASS 0.2.0-M1-FIRST-PLAYABLE
交付内容

Chunk（16×16×128）· Block Registry · Chunk Mesh · Camera · Player · Collision · Gravity · DDA Raycast · Break Block · Place Block · Void · 基础 Save/Load

通过标准
  • 能像极简 Minecraft 一样走、挖、放
  • 视距 6 区块 + 集成显卡：p95 帧时间 ≤ 16.7 ms 且无 > 50 ms 卡顿
  • 石方块空手挖掘耗时 1.5 秒（±0.1 s）
  • 放置遵守相邻支撑规则，不可无支撑 / 越界放置
  • 坠落 4 格 1 伤、3 格无伤、虚空（y < −8）致死
  • 基础存档写入读取后世界状态一致
实测：289 个单元/集成用例全绿，稳态 p95 = 0.685 ms（门禁 MET），fat jar 3.96 MB。

M2

Combat Slice

MVP 必须 PASS 0.3.0-M2-COMBAT-PROTOTYPE
交付内容

手枪 · 弹匣（12）· 手枪弹 · Reload（1.2 s）· Hitscan · Damage · 1 种近战怪 · Death / Respawn

通过标准
  • 能在体素场景中完成一场基础枪战
  • 单发伤害 8（偏差 ≤ 5%）
  • 换弹 1.2 s（±0.1 s）
  • Hitscan 取最近命中，隔实体方块不能命中怪物
  • 距离衰减：≤ 32 格 100%，超出每格 ×0.9，下限 20%
  • 死亡后在 (0,64,0) 螺旋搜索重生；虚空掉落物不坠虚空
最严重的一处缺陷：玩家的枪在存档里静默消失。存档按「方块」表序列化快捷栏， 而手枪的 blockRuntimeId() 是 −1，读档后变回空气。当时 M1 自测 27 项断言全绿， 唯一迹象是日志里两条无人断言的告警 —— 「断言全绿」不等于「没有缺陷」。

Combat Feel & Readability

PRD 之外增补 脚本侧 PASS · 待人工试玩 0.3.1-M2_1-COMBAT-FEEL
交付内容

弹药改为后备无限（弹匣仍 12、仍需按 R，HUD 显示 12 / ∞）＋ 枪口火光 / 更亮更粗曳光 / 撞击粒子 / 命中标记 / 轻微后坐 ＋ 怪物从单盒体改为 8 部件体素人形（行走起伏 / 受击闪白 / 攻击前冲）＋ 第一人称手持物 （枪 / 方块 / 空手，含 idle bob / 开火后坐 / 换弹下压 / ADS 收拢）＋ 最小音频链（lwjgl-openal，5 个程序合成占位音）。

这一轮最值钱的产出

抓出 8 处「已定义、从未被调用」的死代码。 枪口火光、命中标记、开火后坐力全部写在代码里、却从来没有被调用过 —— 编译通过、815 条单测全绿、M1 与 UI 门禁全绿，而屏幕上一样都看不到。

更狠的一处：CombatFxRenderer.init() 在加「枪口闪光」时把曳光的缓冲分配整段顶掉了 （指纹：dispose() 释放三组、init() 只分配两组），门禁 m2 因此崩在 5.6 秒、只跑到第 31 条断言， 而 NPE 堆栈指向渲染循环，离真因隔了三层。修法是把表现层断言从 107 条增到 121 条， 并且只有接线真的存在才会变绿。
第 4 次撞上同一条判据：断言全绿 ≠ 无缺陷。这一次形态最隐蔽 —— 不是断言判错了， 而是那几条行为根本没有对应的断言。

你现在站在哪

位置：M2.2 与 M3 之间。脚本侧已经全部跑通，唯一没关的门是「人坐在屏幕前」这一关 —— 这正好是你给的那段流程里最容易被跳过、也最不该跳过的一步。

眼下唯一该做的事

  • 真人试玩 ≥ 10 分钟，按 M2_2_PLAYTEST_CHECKLIST.md 走完 A–K 共 81 条
  • 格外用力看 怪物可见性 / 手持物 / 命中反馈 / 背包交互 —— 这些正是「写了却没接线」的高危区
  • 试玩结果落成书面证据（M2.1 已有 M2_1_PLAYTEST_EVIDENCE_2026-09-22.md 先例）
  • 关闭 M2.2 后，再决定是否启动 M3

已经稳了的部分

  • M0 / M1 / M1.5 / M2 全部 PASS，各有实测报告与冻结 jar
  • 三门禁长期全绿：27/0 · 75/0 · 160/0，924 条单测 0 失败
  • 性能余量充足：p95 0.6–0.97 ms，离 16.7 ms 门禁差一个量级
  • 构建 → 打包 → 一键启动（原生 .exe 启动器已就绪）全链路打通

!值得留意的一件事：你的文档量已经超过了「精简版」的建议

你提到最容易失败的情况是「策划写了几十页，花半年做系统，最后才发现核心玩法不好玩」。 从量上看，这个项目已经站得比较靠那边了 —— PRD 已经迭代到 v0.3.2（14 章 + 变更日志 + 审计报告），加上技术设计 v0.1.1、技术约束附录、 25 项锁定决策，以及 M0–M2.2 每轮一份验收报告。

但真正把风险压住的不是文档短，而是 M3-GATE 这条硬门禁：它在「核心循环第一次跑通」之后、 在「开始堆内容」之前，强制你先回答「好不好玩」，并且明文禁止用「再加更多枪和怪」来掩盖玩法问题。 这就是精简版流程里那句「可玩原型 → MVP → 小规模测试」的工程化版本。

所以接下来的动作顺序应该是：先试玩拿体验结论 → 再决定 M3 的范围 → M3 完成后必须过 M3-GATE 才动 M4，不要因为「功能不够多」提前进 Alpha。

06

已锁定决策（节选）

共 25 项。下面这些决定了「这个游戏是什么」，也是后面所有里程碑都要对齐的口径。

技术底座
纯 Java + LWJGL，从零手写体素引擎（OpenGL 3.3 Core），第一人称视角
玩法骨架
纯沙盒生存，无结局，靠成就与建造里程碑补长期动力
交付分层
MVP = M0–M3（1 岛 / 1 枪 / 1 怪 / 7 配方 / 无饥饿）· Alpha = M4 · 首版 = M0–M5
枪械
多枪械、有弹药与换弹；不做后坐力 / 散布 / 配件改装（MVP 仅手枪）。开局赠送手枪 + 24 发
敌人
昼夜刷怪 + 远程枪手；强度随时间增强，第 1/3/7/14 天为 ×1.0 / ×1.2 / ×1.5 / ×2.0
合成
背包内直接合成，不做工作台与熔炉；矿物以「矿石 + 煤 → 锭」替代熔炼
生存要素
生命上限 20 + 虚空坠落致死；饥饿 MVP 不启用、Alpha 引入
世界规模
主岛 32×32 + 4 座资源小岛（MVP 仅主岛 + 石矿岛）；视距 6 区块，目标稳定 60 FPS
平台与界面
Windows 优先（fat jar + .bat）；简体中文，无教程引导（保留必要即时提示）
死亡惩罚
掉落全部背包物品并在小屋重生，设置里可关闭
美术音效
先用程序生成占位贴图与临时音效，后期整套替换
联机
首版不做，列为后续迭代；保留最小架构预留（合计 ≤ 2%）
世界种子
对玩家可见、可手动输入
存档格式
混合：区块用二进制，元数据与玩家数据用 JSON
构建链
Maven 3.9.9（升级本机），禁止引入 Gradle
